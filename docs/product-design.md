# 产品设计

## 1. 定位

MossStudio 是面向 MOSS-Image 的桌面创作工作台。目标是把提示词、布局、模型、生成和 Agent 放进一个连续工作流，而不是让用户在启动器、浏览器表单和终端之间切换。

不是：

- 官方 Gradio 的皮肤
- 多 Case 多引擎终端
- 训练器前端
- 模型/算法仓库

## 2. 双窗口

| 窗口 | 职责 |
| --- | --- |
| MossStudio | 创作页 + 底部页面（引擎/模型/设备/训练/画廊/诊断/设置）+ 终端抽屉 |
| Kohaku Trainer | 独立训练工作台；保留 Python/Git 环境 |

没有启动器窗口、设备管理器窗口、终端窗口或每个 Case 一个窗口。

## 3. 创作页

三列 + 中间画布：

```
┌──────────┬──────────────────────────────┬──────────┐
│ 提示词    │  画布 tabs / 工具条 / 生成   │  图层    │
│ 参数      │                              │  布局    │
│ 图库      │  画布（缩放/平移/区域）       │  Agent   │
└──────────┴──────────────────────────────┴──────────┘
```

交互：

- 左右栏宽度可拖拽；可收起为窄轨，再展开。
- 卡片底边可调整高度；卡片可拖到左/右槽或画布浮层。
- 画布滚轮以鼠标焦点缩放；手型/中键平移；工具条有比例/重置。
- 区域框内可直接写提示词；右侧图层列表与画布双向定位。
- 顶部 tabs 管理多张画布：新建、拖动排序、名称/保存状态；未保存草稿保留。
- 底部 tabs 切功能页，不隐藏在工作台图标里。

## 4. 引擎

- 一个 engine 一个 `moss-server` 进程，一个 FIFO。
- 本机与 Linux SSH host 都走同一协议。
- 任务不绑定 Instance；模型和引擎分开选择。
- 默认 system-cuda 包；缺 cuBLASLt 时提示：
  - bundled（+700MB）
  - system + 原生 NVIDIA wheel
- 引擎页管理下载、探测、修补和远端状态。

## 5. 模型与 Project

- 模型是组件化 bundle：dit/text encoder/vae/support。
- Project 保存画布、提示词、图层、模型、设备、系列/页。
- 多张画布用 tabs 表达；不是多窗口。
- 旧 Project `instanceId` 不再使用。

## 6. Agent 与 GBC

- Agent 是可停靠面板，不是独立窗口。
- Provider/对话在本地；写入 Prompt 前必须确认。
- GBC 是外部可选工具；图像图解析导入画布，不参与启动。缺少 GBC 不影响创作。

## 7. Trainer

- 独立窗口，保留自己的 Python/Git 检测、版本与环境。
- 推理侧的 Git/Python 检测不应出现在 MossStudio 主流程。
- 训练与推理共享设备库存，但不共享运行时。

## 8. 非目标

- 不做多个推理引擎实例并行跑同一类 Case。
- 不把官方 MOSS 仓库 clone 进推理链路。
- 不做 macOS CUDA 推理。
- 不把模型权重打包进安装包。
- 不把 GBC/Trainer 的 Python 运行时塞进 Electron。

## 9. 验收原则

- UI 路径存在 ≠ 已验收。
- 真实 NVIDIA/Windows/Linux、安装包、远端 host 必须以实机结果更新 [status.md](status.md)。
- 旧文档/截图只作历史。
